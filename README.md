# CS-230
SNHU CS-230

Briefly summarize The Gaming Room client and their software requirements. Who was the client? What type of software did they want you to design?
Gaming Room built an android game based on the television game show "Win, lose, or draw". They wanted suggestions on how to best scale their game.

What did you do particularly well in developing this documentation?
I did a good job of connecting my understanding of programming with my basic knoweldge of business. I prioritized low cost with market reach. 

What about the process of working through a design document did you find helpful when developing the code?
Thinking about the bigger picture really helped here. Building the game on the cloud and using a Client-Server architecture really helped me understand what each part of the code needs to do. 

If you could choose one part of your work on these documents to revise, what would you pick? How would you improve it?
I think I would put more effort into the storage solution. I started to find a love for security in this course and I wanted to explore options for storing user data away from the game code, but ran out of time.

How did you interpret the user’s needs and implement them into your software design? Why is it so important to consider the user’s needs when designing?
The user was looking for a cheap solution. They designed a game that is, honestly, pretty easy to replicate. In order for them to continue success over their copycats, they needed a system that really set themselves apart. It needs to work fast, it needs to work on almost all devices, and it needs to not break the bank. Selfishly, it's super important to consider the user's needs, because a successful costumer builds a successful business.

How did you approach designing software? What techniques or strategies would you use in the future to analyze and design a similar software application?
I never considered having to develop code on different devices. I guess I kind of assumed building something on java/python/C++ would just work anywhere. I am definetly going to put a lot more thought into who my end user is. Will the software be used on phones, tablets, computers, TVs, gaming console? You really want to figue this out before working on the "release build". You might build a great application for healthcare, but if you built it for computers and they're going to use it on tablets, it could either turn into an inferior product, or you have to rebuild.
